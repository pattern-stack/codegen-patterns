# Jobs wire shapes contract

> Describes current behaviour. Code and tests are authoritative; update this doc in the same change.

`packages/jobs/src/shapes`: the jobs API's wire shapes (`@pattern-stack/jobs/shapes`): the job description and list, the run, its summary and page, the start request and response, the list and wait queries, each a `defineShape` published in snake_case; the vocabulary, re-exported from the engine's model where each list is declared once `as const` with its type derived from it (statuses, triggers, authority levels, limiter scopes (each step's `limiters`: `{ name, per: 'global' | 'tenant' }`, empty for none), page and wait bounds, the dedupe-key pattern); and `jobComponentBase`, a job's `Jobs<Key>` OpenAPI component name. Beside it, `@pattern-stack/jobs/shapes` (`ops.ts`): the superuser `jobsOps` tRPC router's camelCase shapes (jobs with health, runs across tenants, a run, a step's items, events, and the operator's actions), never published on the public API, with the item, event and wait vocabularies and the item and step view schemas the engine's own (a run's and a step's `waiting`, a step's `wait`, the step kind `wait`, the events `step.waiting`, `step.woke` and `step.signaled`), a child's Retry and Skip (`jobsOps.retryChild` / `skipChild`, by parent, step and key), a run's `treeSpend`, the runs list by `parentRunId`, Approve (`jobsOps.signal`: a run's waiting step, its signal and value; a wait step's `signal` in `jobs`, with the form its value is asked with; `JOB_SIGNAL_REFUSALS`), the input form (`input-form.ts`: `jobsOpsInputFormSchema`, `JOB_REF_KINDS` and `jobRef(kind)` (a uuid input field a job marks as a domain id Start run looks up by name; `z.array(jobRef(kind))` is a `ref-array` field, a multi-select of them), and `formFieldsOf` / `formValueProblemOf`, the one reading of a job input's JSON Schema into form fields and their light checks, which the backend's `jobInputFormOf` and the browser's Start run both use), and `jobHealthOf` (`health.ts`), the one definition of a set of runs' health (the newest `JOB_HEALTH_WINDOW`, success over finished runs, durations over completed ones) that the backend and the browser both apply.
